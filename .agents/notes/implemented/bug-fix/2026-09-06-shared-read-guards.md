# Agent Note: 读取与搜索共用敏感名单，并检查真实路径

Status: implemented

整理日期：2026-09-11。文件名日期的依据见 Verification。

## Problem

读取和搜索都会把本地文件内容送入模型上下文。若只有 read_file 检查敏感路径，搜索可以成为另一条读取通道；只检查表面路径也无法识别指向项目外的链接。

## Decision

guard.ts 提供共同的项目范围判断与敏感名单，覆盖环境文件、Git 内部对象、依赖目录及部分私钥路径。单文件读取在词法路径校验后，对可解析的 realpath 再检查项目范围与敏感项。

搜索入口校验目录范围，遍历时过滤敏感文件并跳过递归遇到的符号链接条目；读取和搜索另有文件大小限制。免批准读取必须在工具代码里守边界，[动作批准](../feature/2026-09-02-action-approval-scope.md)不代替这条约束。

这些检查服务于[文件检索流程](../feature/2026-09-05-bounded-file-retrieval.md)，不约束用户批准后的任意 shell 行为。

## Alternatives considered

- 仅在提示词中禁止读取敏感内容：规则可见，但无法约束程序实际执行。
- 每个工具维护自己的封锁名单：实现就近，但规则容易分叉，新增读取通道可能漏项。
- 只用字符串前缀判断项目范围：容易实现，但同名前缀目录和符号链接会使表面路径与实际目标不同。

## Consequences

常见直接越界和敏感路径可在读取前拒绝，代价是文件系统检查增加了 IO，并可能拒绝合理的特殊路径。

当前仍有明确限制：ROOT 自身也被判为不在允许子路径内；realpath 失败时回退词法检查；检查与读取不是原子操作。目录入口的敏感目标检查也不等同于单文件入口，不能声称覆盖同项目敏感目录的所有链接别名。
