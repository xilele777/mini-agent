# Agent Note: 用固定缺陷任务与无密钥 CI 验证交付基础

Status: implemented

## Problem

模型回复和 finish_task 只能说明 Agent 声称完成，不能证明文件正确变化或测试通过。每次临时挑一个任务也难以比较恢复、编辑与预算能力。配置接入后，已有确定性测试需要在干净环境持续运行，不应依赖维护者的密钥和兼容 API。

## Decision

[运费边界模板](../../../../fixtures/shipping-boundary/README.md)提供一个 TypeScript 修复任务：满 100 元免运费，原始实现错误地使用严格大于，三项业务测试中有两项通过、一项失败。任务只允许修改 `src/shipping.ts`，测试、说明和 package.json 保持原样。模板自身是预期失败基线，不加入根目录 `npm test`。

[夹具脚本](../../../../scripts/eval-fixture.mjs)的 `new` 在被 Git 忽略的 `.mini-agent-eval/` 下创建全新副本，不覆盖旧任务；`check` 先比较非目标文件的 SHA-256 与文件集合，再启动真实测试进程。目标文件缺失、其他文件变化或测试失败均不能验收通过。调用 finish_task、修改测试或只输出成功文字不能改变验收结果。

`selftest` 在专用临时副本核对原始缺陷、已知修复和无关文件变更三个场景；清理前核对真实路径，且仅删除该次自检创建的目录。自检证明夹具和判定机制工作，不证明模型已自主修复任务。每次重新评测都新建副本，原有结果留存。

[CI 工作流](../../../../.github/workflows/ci.yml)在 Windows 与 Ubuntu、Node 22 下定义安装依赖、类型检查、核心测试、笔记校验、看板测试和夹具自检，不配置密钥、不运行在线 doctor。当前只有工作流定义与本地命令验证，远程 GitHub Actions 结果需首次实际运行后确认。

本夹具服务于[完善版 v1 路线](../../proposed/architecture/2026-09-20-practical-mini-agent-v1.md)的贯穿任务。恢复故障窗口、编辑冲突和总预算用例随对应阶段补充，不能把当前三个业务断言视为完整 Agent 评测。

## Alternatives considered

- 每次使用真实项目的新问题：任务更贴近使用，但难以保持相同起点和成功判据；先用固定小任务验证机制，再加真实仓库任务。
- 在原始模板上直接修复再恢复 Git 文件：操作少，但容易误删或覆盖已有运行成果；全新副本略占磁盘空间，换取各次任务互不覆盖。
- 只根据测试退出码判定：成本低，但修改测试也可能制造成功；额外核对非目标文件，约束该夹具允许的变化范围。这仍不是抵御恶意代码的沙箱。
- CI 调用真实模型：覆盖兼容服务，但引入密钥、费用、网络和模型波动；确定性检查进 CI，真实模型保留人工验收证据。

## Consequences

每次任务有固定起点与可复查结果，失败输出和不允许的文件变化可直接定位。代价是维护模板、运行脚本和 CI 配置，并保留人工记录模型／配置、请求数、token、耗时与干预次数的责任。

模板故意保留一个缺陷；新增根目录测试发现规则时必须避免将其误当作普通通过用例。副本目前复用根目录安装的 tsx，尚不是可脱离本仓库独立安装的项目。检查只核对副本内文件，不宣称能检测或限制 Agent 在副本外的所有副作用。
