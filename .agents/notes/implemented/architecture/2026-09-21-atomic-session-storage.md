# Agent Note: 会话快照以同目录原子替换保存并显式持有独占锁

Status: implemented

## Problem

直接覆盖 JSON 在部分写入失败时可能破坏上一份状态。把读取错误统一回退为空状态，会让损坏会话在后续保存时被覆盖；两个进程各自写入也可能相互丢失更新。阶段 11 需要先建立可验证的存储边界，再接入具体会话格式和主循环。

## Decision

[session-storage.ts](../../../../src/session-storage.ts) 提供接收 JSON 数据 Zod schema 的读取与保存函数，以及独立的会话锁。`readSnapshot` 仅在 `ENOENT` 时返回 null；JSON 解析错误、schema 不符和其他读取错误继续报错，保留原文件。上层必须先获取锁、读取校验，成功打开或确认缺失后才能保存；写函数不自行判断是否允许覆盖一个既有会话。

`writeSnapshot` 先校验、序列化，再在目标同目录以 `wx` 创建唯一临时文件，写入、同步、关闭后通过 rename 替换目标；不先删除旧文件。失败时清理本次临时文件，替换入口提供窄注入用于模拟提交前失败。调用方必须顺序等待保存，锁本身不串行化同一进程中的调用。

`acquireSessionLock` 以 `wx` 排他创建 session.lock，记录 PID 与时间。锁由文件存在与否表达，文件句柄关闭不等于释放；返回的释放函数只执行一次，避免旧释放函数删掉新持有者的锁。打开期间持有，正常关闭后删除；遗留锁保守拒绝，不按 PID 或锁龄自动抢占。

源码入口通过[完善版路线](../../proposed/architecture/2026-09-20-practical-mini-agent-v1.md)关联本决定。[agent.ts](../../../../src/agent.ts) 已通过会话入口使用本模块；会话 todo 与[异常保留规则](../bug-fix/2026-09-06-tool-result-history-recovery.md)共同使用快照。

## Session ownership

[session.ts](../../../../src/session.ts) 在真实项目根目录的 `.mini-agent/sessions/<UUID>/` 新建与打开会话。目录 ID、快照 ID 与规范化项目根必须匹配；复制到其他项目的快照不能直接打开。新建不合并已存在的会话目录，打开不存在的会话也不创建空目录。

会话句柄持有状态与锁；snapshot 返回深副本，update 在独立草稿上执行回调、校验身份与结构、保存，成功后发布内存状态。回调可等待完成，但用途限于修改草稿，不构成外部副作用事务。busy 标记拒绝重叠更新及保存中关闭；close 后禁止继续更新。

[session-schema.ts](../../../../src/session-schema.ts) 的版本 2 保存文本与 function calling 消息、startsTurn、会话 todo，以及带 turnId 的轮结果与动作记录。schema 校验轮边界、动作归属及工具结果配对；todo 编号唯一且小于 nextId。可选消息字段在解析出口省略 undefined，以满足 exactOptionalPropertyTypes。版本 1 缺少动作证据，拒绝加载并保留原文件，不自动迁移。

列表只读已提交快照，逐条返回正常摘要或错误，不获取写锁或自动移动文件。旧项目 todo 保留并提示存在，不被新会话继承；当前 todo 工具由会话句柄工厂创建，与主循环使用同一状态所有者。

[session-runner.ts](../../../../src/session-runner.ts) 在模型请求前保存用户输入，等待每个检查点提交消息、动作及轮结果；更新使用最新草稿，保留工具刚提交的 todo。恢复将 pending 补为 not_executed、started 补为 uncertain，并追加有标签的恢复说明、将中断轮标为 failed。恢复不请求模型、不重放工具，CLI 等待用户新指令。完整历史持久化，裁剪只作用于模型视图；历史中存在不确定动作时另加核查提示。

## Alternatives considered

- 直接覆盖 JSON：步骤少，适合早期教学，但部分写入可能破坏唯一快照。同目录临时文件保留提交前的旧版本，代价是额外写入、同步与清理。
- 先删除旧快照再重命名：避免处理替换语义，但删除后失败会丢失唯一可用版本，因此不采用。
- 自动根据 PID 或时间抢占锁：恢复操作方便，但 PID 复用、进程检查权限和长任务会导致误判；当前先要求核查原进程，接受人工清理遗留锁的成本。
- SQLite：事务与并发控制更完整，但现有目标是单写入者、可检查的本地快照；尚不需要查询或多会话事务，引入另一存储系统不能解决外部工具副作用与快照之间的事务缺口。
- 暴露可变内存对象或先发布内存：调用代码短，但容易绕过保存或在保存失败后使用未提交状态；句柄采用深副本和草稿，接受复制完整历史的成本。
- 自动移动损坏文件：目录更整洁，但只列出会话也会修改文件位置并增加锁与移动失败边界；当前逐条报告错误并保留原文件。
- 只在轮末保存或自动重放未完成调用：前者丢失轮中副作用证据，后者可能重复执行；采用执行前后等待检查点及保守恢复，接受额外 IO 和人工核查成本。

## Consequences

读取错误与无文件明确分开，提交前故障不会直接改写旧快照；锁阻止遵循协议的第二个写入者。代价是每次保存需要额外 IO，进程崩溃可能遗留锁及临时文件。外部程序直接改文件不受该锁约束。

文件内容同步不等于断电持久性保证：当前未做目录同步或断电故障实验。原子替换也不把 shell、文件修改和会话保存合成事务。项目绑定、会话身份及坏条目隔离由数据层负责；动作不确定状态由恢复入口展示并要求核查，不能保证外部命令恰好执行一次。出现多写入者或更强断电保证的实际需求时重新评估协议。
