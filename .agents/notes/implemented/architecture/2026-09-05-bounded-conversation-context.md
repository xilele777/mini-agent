# Agent Note: 用结果截断与整轮裁剪控制发送给模型的历史

Status: implemented

整理日期：2026-09-11。文件名日期的依据见 Verification。

## Problem

工具输出和跨轮消息会持续积累。如果每次都发送全部内容，成本与上下文压力不断增加；随意切掉若干消息又可能丢失当前目标或拆开调用与结果。

## Decision

工具结果超过 4000 字符时，公共上下文层保留开头 3000 和结尾 1000 字符，并明确指出中间省略。当前主循环每次发送前从完整原始历史构造请求视图，按预算删除完整旧轮，保护首轮前缀及当前轮；视图裁剪不删除持久化历史。固定六轮的 trimHistory 保留为已有工具函数及其测试，正式主轮不再调用。

真实轮次由[startsTurn 标记](2026-09-11-user-turn-boundaries.md)确定，不能靠消息数量或角色猜测。单次返回不完整时，模型应使用[定位和分页工具](../feature/2026-09-05-bounded-file-retrieval.md)继续取证。

每次模型响应有 usage 时打印 prompt、completion 和 total，供观察请求规模；工具调用结构遵循[原生协议](2026-08-31-native-function-calling.md)。

2026-09-21 新增 [context-budget.ts](../../../../src/context-budget.ts) 并接入请求链路。`buildContext(history, tools, budget)` 复制请求视图、去除本地标记并截断工具结果，将窗口扣除输出预留和安全余量后作为输入预算；从最早旧轮开始整轮移除，保护首轮前缀与当前轮。无 startsTurn 时整份历史受保护，删完旧轮仍超限时返回无 messages 的失败分支。函数依赖调用方提供配对完整的历史，不负责修复异常配对。

计数对文本 messages 与工具 schema 的 JSON 使用 UTF-8 字节数粗估，并增加包装余量；内容块数组明确拒绝。该方法不绑定兼容模型的 tokenizer，输出字段明确命名为 estimatedInputTokens，不宣称服务端 token 硬保证。后续请求接线和摘要范围见[阶段 12 路线](../../proposed/architecture/2026-09-20-practical-mini-agent-v1.md)。

### Request wiring

[runtime.ts](../../../../src/runtime.ts) 将统一配置作为必填 contextBudget 注入主／子循环；两者每次请求均检查当次历史及工具集合，携带 maxOutputTokens。主轮超限经 finish/checkpoint 保存 budget_exhausted，保留已完成动作及结果；子任务超限返回明确的未完成原因，主轮据此决定下一步。

子 Agent 仅有一个真实任务轮，最终总结提示属于该轮，不能通过删除任务开头腾空间。最终请求先撤下工具再估算，仍超限则不额外请求；子历史保留原始工具返回，仅发送视图与日志截断，避免重复截断。子历史仍不持久化。

[llm.ts](../../../../src/llm.ts) 将输出上限写入所选请求参数，且限制其不得超过配置的输出预留。默认 max_completion_tokens，兼容服务可显式选择 max_tokens，不自动撤掉限制或重发。适配器将 context_length_exceeded/context_window_exceeded 转换为固定 ContextBudgetError；主轮据此结束为预算耗尽，子轮返回明确原因，其余异常继续沿用失败路径。具体配置与默认值归[统一配置](2026-09-21-validated-runtime-config.md)。

## Alternatives considered

- 完整保留全部消息：信息最充分，但无法控制长会话的上下文增长。
- 按固定条数切消息：实现简单，但可能保留孤立的 tool 结果或截掉用户目标。
- 立即引入模型摘要和长期记忆：能保留更多跨轮信息，但会增加额外请求、摘要失真与维护逻辑，当前先使用可检查的固定策略。
- 固定字符数除以四估算：简单且估值更小，但中文、代码与兼容模型的分词差异会降低余量可靠性；当前文本模块采用更保守的字节粗估，接受过早裁剪的代价。
- 模型专用 tokenizer：能提高窗口利用率，但需要匹配实际模型及服务端包装；当前兼容服务尚不固定，保留为有 usage 对照后的适配方向，未进行计数方案的对比实验。
- 主／子循环各自使用隐式默认预算：修改测试入口更少，但漏传配置难以被发现；采用必填依赖，由 runtime 统一注入。
- 只在真实用户输入时检查：调用次数少，但工具观察及内部提示会在同轮继续增长；每次模型请求前检查，接受重新估算的开销。
- 单一输出参数或不支持时自动撤掉限制：配置少或更容易请求成功，但不同兼容服务的协议差异可能使输出预留失效；选择显式参数配置并保持限制。

## Consequences

上下文策略集中在一处，代价是省略内容和早期轮次不可由模型凭记忆恢复。附加截断说明会让结果略超过 4000 字符，估算使用附带说明的实际请求视图。

shell 工具自身还有输出截断，公共层看到的结果可能已丢失一部分内容。usage 日志是观察值，不能单凭单次回落证明所有任务的费用已封顶。

预算模块保持原始历史与嵌套工具调用隔离，代价是复制与逐轮重新序列化的开销，以及保守粗估可能丢弃本可容纳的旧轮。生产主／子请求已检查预算且实际请求体携带生成上限，但估算与兼容服务的严格执行不能当作已获精确硬保证。摘要与失败回退已接入；全轮统一 token／时间／委派／重试账目由[运行控制器](2026-09-22-runtime-resilience.md)实施。

### Persistent compaction

[compaction.ts](../../../../src/compaction.ts) 在会话请求需要裁剪旧轮时，每个真实用户轮最多尝试一次摘要；只选择一次请求能容纳的连续完整旧轮，摘要源包含此前摘要、原始消息及轮／动作状态。摘要输入不截断，无法容纳一个完整旧轮时直接沿用裁剪。摘要无工具，生成空间不超过主轮输出预留且最多 1024 token；主轮与摘要共用请求次数，发摘要前至少剩两次，保留一次正常请求。

[context-summary.ts](../../../../src/context-summary.ts) 定义 through 排他性消息上界、原文 SHA-256 指纹和非空且不超过 6000 UTF-8 字节的正文。覆盖边界须是下一真实轮的起点，来源指纹必须匹配；摘要作为有来源标签的 user 材料置于固定前缀后，不设置 startsTurn，也不提升为 system 指令。后续只拼入 through 之后的原文；追加摘要时合并前次摘要，保持连续覆盖。指纹用于发现来源不一致，不证明模型摘要语义准确。

候选摘要必须正常结束、无拒绝或工具调用、确实缩短视图且新的请求预算可满足，才通过会话原子更新保存；保存前再次核对来源及原摘要未改变。保存成功后才发送新视图。生成、格式校验或保存失败保留原摘要与全部历史，回退到此前已确认可发送的裁剪视图，同轮不重试。旧摘要本身放不进更小的新窗口时，仅本次退回原始历史裁剪；原始当前轮也超限则零请求停止。AbortError 继续向外传播，不因回退继续执行。

[session-runner.ts](../../../../src/session-runner.ts) 每个用户轮创建独立压缩器，并将恢复后的不确定动作提醒放在预算计算前；原先在 createStream 包装中追加提醒会漏计开销，现已消除。主循环保留完整历史做检查点，只有派生视图受裁剪与摘要影响。新快照 v3 及 v2 无损读取归[会话存储](2026-09-21-atomic-session-storage.md)。

取舍：直接覆盖原文更省磁盘但失去核查依据；一次循环摘要所有旧轮能覆盖更多历史，却增加请求消耗与失败链路。当前保留原文并只做一次有界摘要，接受剩余旧轮仍可能被裁掉。摘要保存错误若一律致命会阻止本可继续的任务；这里仅对派生摘要允许回退，动作检查点保存失败仍立即停止。主／摘要局部合计次数和全轮共享预算同时生效，取消及 RunBudgetError 不能被摘要回退吞掉。
