# Agent Note: 纯配置解析与启动诊断分层

Status: implemented

## Problem

原先模型配置在 `src/llm.ts` 导入时读取环境并校验，模型名、shell 和请求次数分别固定在多个模块中，文件读取工具另行解析环境变量。配置错误缺少统一出口；将这些读取直接搬进一个全局对象，又会使只导入业务模块的测试依赖真实环境。

这是[完善版 v1 路线](../../proposed/architecture/2026-09-20-practical-mini-agent-v1.md)阶段 10 的配置边界。配置、运行接线、doctor 与启动失败诊断均已接入，具有模拟回归和真实模型证据。相关职责见[本地 CLI 与 SDK](2026-08-30-local-cli-and-sdk.md)和[可测试主轮执行器](2026-09-20-testable-turn-runner.md)。

## Decision

纯函数 `loadConfig(env, platform)` 只校验显式输入，返回只读的 `AppConfig`。模块导入与函数执行均不读 `.env`、不访问磁盘、不发模型请求。环境加载由启动入口负责，业务模块接收已校验配置；doctor 复用同一解析器，再检查 shell 与兼容 API 的实际可用性。

学习者已接入 [config.ts](../../../../src/config.ts)、[runtime.ts](../../../../src/runtime.ts)、[doctor.ts](../../../../src/doctor.ts) 与相应测试。已校验配置进入模型、主／子 Agent 注册表、读取与命令工具，doctor 的离线及在线探针均有通过记录。

- API key、base URL 和模型名必填。保留兼容 API 的自定义路径，不猜测或自动补 `/v1`；URL 只接受 HTTP(S)，不接受认证信息、查询参数或片段。格式合法不证明协议端点可用。
- Windows 显式填写绝对 shell 路径，不沿用开发者机器上的 Git 安装位置；其他系统缺省 `/bin/sh`。解析器不检查文件存在，doctor 再做可用性诊断。
- 请求超时缺省 120000 毫秒，命令超时 30000 毫秒；超时不能超过 Node 定时器范围。主请求和子 Agent 局部次数缺省 10 与 6；文件读取缺省 5 MiB，沿用 `MINI_AGENT_MAX_READ_MB` 并换算成字节。
- 未提供的可选项使用默认值；显式填写空白、非正数、非整数次数或其他非法值时报告错误，不静默回退。现阶段不添加尚无执行机制的 token 或整轮总预算开关，避免配置存在却不生效。
- 报错只包含固定环境变量名，不直接抛出可能携带输入值的校验错误。成功返回的配置仍包含密钥，不能整体打印或写入轨迹；doctor 只输出固定诊断分类。
- `AppConfig` 从函数返回类型推导，避免手写类型与实际解析结果漂移。配置对象扁平且冻结，不承担生命周期或工具状态存储。

### Startup wiring and doctor

`createRuntime(config)` 组装模型流工厂、带读取上限的文件工具、带 shell／超时的命令工具，以及主／子 Agent 的注册表和局部请求上限。主／子循环必须接收模型入口、注册表与次数，不再动态加载环境配置。委派工具只接收 runner，由组装入口负责连接子 Agent，避免工具集合与循环互相建立隐式配置依赖。

仅 CLI 入口加载 `.env` 并调用解析器；`llm.ts` 改为显式配置工厂。模型请求先关闭 SDK 隐式重试，并用覆盖整个流消费过程的超时信号限制等待；全轮取消和含摘要／重试的总预算仍按路线后续接入，不能把单请求超时写成端到端取消已完成。

doctor 分为可导入的检查函数与独立 CLI。默认只做配置及 POSIX shell 非交互探针，明确显示模型检查被跳过；`--online` 才发起一次真实流式请求。在线探针要求返回指定函数及参数，由现有流组装器检查完整性，不执行任何模型工具。诊断只打印固定分类信息，不打印密钥、完整配置、模型文本或服务端原始错误正文。

当前 shell 接入范围为 Windows Git Bash 与 Linux sh/bash；配置绝对路径并不意味着任意 shell 方言都受支持。阶段 10 的简单 shell 探针不证明完整子进程树清理，后者仍在阶段 13 验收。

## Alternatives considered

- 模块导入时建立全局配置：使用方便且只解析一次，但会把环境依赖传给业务模块和测试，并且 doctor 难以控制启动失败的展示；采用纯解析函数，由入口控制何时校验与注入。
- 配置错误时尽量沿用默认值：启动更宽容，但拼错预算或超时会静默改变实际行为；只有未提供的可选字段采用默认值，显式非法值直接报错。
- 解析时自动探测 shell 和 API：可以一次得到最终可用配置，但会使每个配置测试依赖机器、网络及密钥；分成纯解析和 doctor 探测两层，接受格式通过后仍可能诊断失败。
- 保留全局注册表并在启动时修改其中的工具配置：改动位置较少，但容易让 schema、实际执行与子 Agent 使用不同配置；用启动工厂显式构建集合，代价是现有循环测试需要传入依赖。
- doctor 默认发起模型请求：一次命令能覆盖更多问题，但每次本地排错都会依赖网络并可能计费；默认离线并明确 SKIP，在线检查通过 `--online` 选择。

## Tested boundaries

- 不需要真实 API 环境即可导入模块，用输入对象检查默认值、覆盖与单位换算。
- 缺失模型字段、Windows 未配置 shell、非法数值和不允许的 URL 均被拒绝；错误不包含原始输入值。
- 自定义 base URL 路径保持，shell 存在性不在纯解析器中检查；输出只读且不修改输入对象。
- CLI 和 doctor 复用解析器，业务导入不引发环境读取或网络访问；运行组装由常驻模拟回归和真实 doctor／REPL 记录验证。
- CLI 启动缺少必填项时，报告字段名且以非零状态退出；ConfigError 必须由覆盖配置加载的外层 catch 处理，不能仅放在 runTurn 的内层 catch。

## Consequences

集中配置与显式组装使主／子 Agent 使用一致配置，启动错误、网络探针和纯函数测试各有可观察边界。代价是调用方必须提供完整依赖，模型名和 Windows shell 也需要首次显式配置。纯函数通过仅证明配置结构符合约定，服务兼容性仍依赖 doctor；单请求超时与局部次数不构成全轮取消或共享总预算。
