# Agent Note: 独立维护教练方法、项目学习资料与工程决策

Status: implemented

整理日期：2026-09-11。文件名日期的依据见 Verification。

## Problem

学习项目同时需要工程理由、教学分工和理解证据。若把背景与阶段记录塞进第三方笔记工具，升级工具和迁移新项目都会携带无关事实；全部保存在本地交接中又难随仓库交接。

## Decision

项目入口组合原版决策笔记 Skill 与独立 learning-coach。前者负责工程决定的记录，后者负责讲解、练习、review 和学习交接；项目学习配置保存编辑分工，简短进度保存代码状态、验证结果和理解证据。

学习者默认维护核心源码，AI 在授权范围内维护管理文件；卡住时可以给完整参考、逐块讲解并留小改造。用户明确代改的要求可覆盖默认分工，已有授权不重复确认。

这一分工服务于[手写 CLI 的学习目标](../architecture/2026-08-30-local-cli-and-sdk.md)，采用[验证范围约定](../testing/2026-09-05-verification-scope.md)区分实现通过与理解掌握。教学不新增工程笔记的状态或分类。

## Alternatives considered

- 只使用既有 HANDOFF：信息集中且已有内容，但过程、约定和决策混合，docs 目录又不随当前 Git 保存。
- 直接修改第三方 Skill：入口少，但升级需合并个性化补丁，新项目会继承旧背景。
- 把全部教学方法放在 AGENTS.md：加载直接，但入口变长，通用方法无法独立复用。

## Consequences

通用方法、上游工具和项目资料可分别迁移，代价是需要沿入口读取相关文件并保持职责清楚。源码补录笔记采用可检索路径与笔记到源码的链接，不为了管理文档直接改动学习者的 src。

工程笔记描述理由与代价，进度文件记录练习与证据；“待观察”不表示已经或尚未掌握。上游工具缺陷通过项目适配处理，不把教学逻辑混入其目录。
