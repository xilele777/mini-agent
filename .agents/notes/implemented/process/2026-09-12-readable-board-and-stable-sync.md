# Agent Note: 用独立的项目地图连接运行流程、开发进度与决策依据

Status: implemented

首次整理：2026-09-12；当前展示与同步行为核对：2026-09-13。

## Problem

原看板信息密度高，卡片与装饰占据阅读空间，用户希望改为浅色、留白充足的文档工作台。目录热更新时，同一天的笔记又会反复变换顺序，打断查找与阅读。

导航已经提示当前位置，正文仍重复项目或模块标题、导语、节点职责和页脚说明。这些介绍占据首屏，分散了对流程、实际做法和决策正文的注意力。

资料页沿用左侧目录、右侧详情的 Wiki 布局，地图又有常驻的侧边说明。切换入口时导航方式改变，流程空间被固定面板挤占；用户希望直接在流程中展开内容，阅读后回到原来的位置。

按日期、类别或模块排列笔记，仍需要读者自行拼出项目如何工作。当前笔记全是 implemented，这些状态不能说明下一步安排或学习掌握程度。用户需要先看懂任务在各部分之间怎样流转，并直接找到当前实现、待验证项和下一步；只有需要追溯时才阅读全文。

旧实现将文件系统遍历顺序直接传入只按日期排序的数组，并在每次检查后无条件重画所有视图。同日期、同引用数没有确定的次级顺序；focus 与定时检查也没有统一的并发入口。

## Decision

项目看板首页展示可点击的运行流程。主循环、返回路径、辅助状态与控制分支按[项目展示配置](../../../board.json)固定布局；节点展示当前行为、限制，并链接决策依据与源码入口。图中关系根据实际源码和设计决定整理，不从笔记互相引用的数量推断运行时依赖。Mini Agent 的提问分支回填回答后继续当前轮，完成和暂停分支结束本轮、等待新指令。

所有视图共用顶部横向导航，模块通过资料页筛选器选择，移除常驻侧目录和面包屑；页面级 h1 仅保留给辅助技术与键盘焦点。图内和分区使用一个短标题，阅读层只显示一次笔记原题。模板移除介绍段落、操作导语、重复资料入口与页脚统计；配置移除项目独立标题、项目／地图／模块的 description 和节点 purpose 字段。实际行为、限制、笔记全文及有明确用途的筛选计数继续显示。

流程画布占据完整内容宽度，默认收起节点说明。点击节点后只展开一处详情，再次点击或关闭即收起。桌面详情放在节点所属行下方；窄屏主流程与分支详情紧接所选节点，辅助节点共用行下方的展开区。详情展示实现、限制、源码，以及所选决策的取舍和验证节选；备选方案按需展开，切换依据和阅读全文使用同一处入口。内容高度变化时重算窄屏回路线。

顶部的当前实现和下一步候选，以及下方的待验证项，按配置中的章节名读取[现有进度](../../../learning/progress.md)。可选的学习区域读取实践记录、理解证据与练习入口，可在页面折叠或通过配置关闭。教学方法仍由[独立教练约定](2026-09-11-learning-workflow-and-notes.md)管理，不扩展笔记的 class 或 lifecycle，也不从 implemented 状态推断学习者已经掌握。

完整决策、演进记录和方案取舍保留独立入口。资料页使用卡片集合与筛选器，笔记和进度原文在居中的原生 dialog 中打开，正文独立滚动，关联笔记放在正文下方。关闭按钮、Esc、点击背景或浏览器后退关闭阅读层，恢复原视图、筛选、节点、滚动位置和焦点。首次阅读增加一个浏览器历史项，关联资料在此项中替换，层内“返回上一份资料”恢复前一份正文及其位置。阅读状态与两处滚动位置写入历史项，以支持刷新和前进；页面滚动时延迟保存，离开前补存，避免仅在 pagehide 保存而错过 Chromium 的重载历史。

配置中的 groups 组织资料筛选与无地图时的模块集合，笔记去重分配，新增、改名或未配置的记录进入标准类别。缺少展示配置时回到按类别浏览全部笔记，不隐藏记录。

页面模板、浏览器逻辑、资料适配器和生成脚本由项目独立维护，原版 Skill 保持原样。项目名、流程节点、源码路径和学习资料章节留在可选配置中。节点的简短行为解释用于浏览，详细理由仍以决策笔记为依据；阶段和理解证据只在进度文件中维护。两种输出共用解析器，沿用[完整章节读取](2026-09-11-complete-board-sections.md)。

连接项目根目录或 .agents 时，一次检查读取笔记、board.json 和配置明确引用的 Markdown 资料；相同来源只读一次。仅连接 notes 时只显示该目录的笔记，不继承原项目的地图和学习状态。未连接的 board.html 显示生成时的项目概览，完整决策需要连接目录；离线快照同时内嵌笔记。连接操作与状态集中在顶部，显示未连接、离线快照、自动同步或同步失败；手动检查仅在连接后出现，目录名与检查时间放在状态提示中。

检查请求串行执行，重叠触发合并为后续一次检查。内容指纹包含笔记路径与正文、展示配置及资料正文，不依赖文件大小、时间或遍历顺序；同日期和同引用数使用规范路径确定顺序。未变化时不提交数据或替换 DOM；变化时保留节点展开、依据选择、备选和学习区域偏好、当前阅读资料、焦点及两处滚动位置。切换目录使旧读取失效。读取失败或配置尚未写完整时保留最后成功数据；明确删除的配置回退到笔记浏览，缺失的资料或章节显示提示，当前笔记删除后仍在阅读层显示可关闭的缺失状态。

## Alternatives considered

- 只覆盖原页面的 CSS：改动集中，能快速改变配色，但阅读结构、详情缺失和刷新状态仍受原模板控制；独立页面更符合这次重新设计的范围。
- 继续把模块笔记清单作为首页：便于查找和完整阅读，但运行关系与当前开发重点仍依赖读者自行归纳；清单作为资料入口保留。
- 自动把笔记引用绘制成架构图：不需要额外维护关系，但引用只能证明相关背景，无法证明调用顺序、状态供给或控制权返回位置；当前使用有源码依据的明确流程配置。
- 只补一个排序条件：可以稳定同日期的先后关系，但每次扫描仍会替换 DOM，无法保留焦点，也没有处理重叠读取与失败快照。
- 引入前端框架和开发服务器：组件与更新机制成熟，但看板目前规模小，主要需要直接打开 HTML 和本地目录读取；项目采用无新增依赖的模板生成与原生浏览器逻辑。
- 将 Mini Agent 的流程、阶段和教学方法写进渲染器或上游 Skill：配置更少，但其他项目必须修改通用工具。独立展示配置与资料来源允许替换项目内容或关闭学习区域，代价是维护节点摘要及其依据链接。
- 将介绍折叠或增加精简模式：仍可按需展开完整导览，但要继续维护重复说明和额外偏好；已有导航足以定位，当前直接删去这层内容与配置字段。
- 保留可折叠的左侧模块目录：适合连续查阅文档，但仍以目录层级组织页面，地图与资料的导航方式也不统一；模块筛选与顶部入口足以覆盖当前查找需求。
- 将节点说明改成右侧抽屉：可以减少常驻内容，但宽屏仍要在流程和侧栏间来回看，窄屏抽屉还会遮住节点；当前就地展开，代价是下方内容随之移动。
- 全文跳转到独立详情页：地址与整页阅读直观，但离开流程后需要重新建立当前位置；居中阅读层保留背景，代价是显式维护阅读历史、焦点和滚动恢复。

## Consequences

读者可以先沿流程理解项目，再定位当前实现、缺口和详细依据。展示层与学习区域可独立迁移，未改变内容的同步保持页面稳定。代价是项目负责展示逻辑、有限的 Markdown 渲染、资料适配和同步回归；上游看板的界面更新不会自动进入本项目。

精简后的首屏直接呈现进度和流程，模块页直接进入筛选与清单。首次阅读依靠节点标签和实际内容，没有独立的导览介绍；后续只有观察到具体入口无法理解时，才在该入口补充必要提示。

画布只保留一个展开节点，适合沿流程查看，不提供多个节点详情并排比较。全文阅读时背景暂不可操作，跨资料返回由阅读层管理；资料关联仍完整保留。布局不新增依赖，但需要维护原生 dialog、响应式详情位置与浏览器历史之间的状态边界。

流程关系与简短行为解释需要随实现维护，资料章节改名时需要同步配置；校验能发现无效关系与缺失路径，不能证明描述符合源码。当前布局支持二至六步主流程、辅助节点、一个可选回路和控制分支，更复杂的关系需要扩展布局。模板或脚本修改后重新生成并刷新；连接完整项目后的配置、笔记和进度变更无需重新生成页面。

自动同步是可见页面每三秒检查，并在返回页面时检查，并非操作系统文件监听。每次检查读取笔记和引用资料，当前小型项目可接受；规模扩大后再依据实际开销考虑缓存。保存过程中短暂解析失败会保留旧内容，下一次检查恢复。

本地目录连接依赖 Chrome 或 Edge 的文件访问 API 与浏览器授权。目录句柄、筛选、节点与学习区域偏好按页面路径和项目名保存；旧版保存的 notes 句柄仍能浏览笔记，需要重新选择项目根目录才能读取同级配置与学习资料。源码相对链接仍以生成页面所在项目为基准。
