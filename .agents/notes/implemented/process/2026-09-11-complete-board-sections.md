# Agent Note: 看板完整读取笔记章节，并展示验证依据

Status: implemented

整理日期：2026-09-11。更新日期：2026-09-12。文件名日期的依据见 Verification。

## Problem

看板的章节提取表达式启用多行模式，又以行尾作为章节结束条件，导致一节只保留第一行。多段决定和第二条以后的备选会在界面消失，即使 Markdown 文件本身完整。

## Decision

笔记仍采用标准的 Problem、Decision、Alternatives considered 和 Consequences 结构，并允许多段内容。项目解析器按二级标题识别完整章节，保留到下一个标题或文本结束；代码块内的标题不切断正文。

本地目录读取和离线打包共用同一解析器，原始 rawBody 保留。阅读页展示 Verification 及其他自由章节，摘要视图继续使用主要问题、决定和备选字段。原版 Skill 不改写；独立页面的布局与同步由[阅读工作台](2026-09-12-readable-board-and-stable-sync.md)约定说明。

笔记之间使用有理由的相对链接，使看板可以计算引用并展示关联；历史补录依据可核实记录归位日期，不为填满状态栏虚构被否决的提案。这沿用[工具与项目配置分开维护](2026-09-11-learning-workflow-and-notes.md)的约定。

## Alternatives considered

- 只增加笔记数量：能补齐主题，但解析器仍会丢掉每节后续内容。
- 把每节全部压成一行：可以迎合当前解析，但破坏 Markdown 的可读性，备选项也难以独立展示。
- 直接修改上游模板和构建脚本：立即有效，但会给升级引入本地分叉；独立项目解析器可以显式记录并校验兼容范围。

## Consequences

本地连接和离线看板都能读取完整章节，代价是项目需要维护解析器与笔记格式的兼容性。读取到缺少标题或状态的文件时应报错，不将未完成保存的内容当成有效记录。

看板统计引用关系，不证明某个决定更正确；已有方案的备选会进入方案取舍视图，无需伪造 rejected 笔记。原来的生成后正则补丁由共用解析器接替，避免同时维护两套修正。
