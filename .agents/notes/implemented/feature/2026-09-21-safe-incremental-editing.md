# Agent Note: 文件候选绑定批准，提交前复查基准版本

Status: implemented

## Problem

完整覆盖会丢掉未读到的内容；等待批准期间，编辑器或另一进程可能改变文件。只用工具名和参数记住批准，不能证明用户看到的修改仍适用于当前文件。旧 write_file 还能绕开新的增量编辑保护。

## Decision

read_file 返回整文件字节的 SHA-256，包括分页和空文件。edit_file 接受 path、expected_sha256、old_text、new_text，只允许旧文本精确且唯一匹配；重复匹配包含重叠出现，零匹配、过期指纹和无变化在批准前拒绝。支持无 NUL 的 UTF-8，编辑及新建上限 1 MiB，不自动转换换行；未修改内容、BOM、CRLF 和末尾换行保留原状。

工具的异步 prepare 生成不可变 PreparedAction，闭包捕获目标、基准、候选和执行函数。主轮把同一个 action 的完整变化 diff 交给批准，再调用其 execute；不在批准后依据可变模型参数重新生成内容。批准键绑定绝对路径、基准指纹与候选指纹，文件工具禁用 a 缓存，逐次使用 y/n。预览显示全部增删行、三行上下文、末尾换行及 CR 标记；终端控制字符转为可见转义。

提交先复查路径及指纹，再在同目录创建排他临时文件、写入并 sync，提交前再次复查文件指纹、身份与模式。已有文件通过 rename 原子替换；新文件通过 link 排他发布完整临时文件，再删除临时名字，避免覆盖批准后出现的同名文件。新建可以创建父目录。失败清理本次临时文件，已创建的空父目录可保留。Windows／POSIX 支持硬链接的本地文件系统是新建的使用范围；不支持时明确失败，不回退覆盖。

write_file 只新建，已有文件必须 edit_file。两个工具都拒绝项目外、敏感路径、符号链接／junction 组件、目标硬链接和非普通文件；不存在的后缀检查已有父目录。读取和搜索沿用[共同路径边界](../bug-fix/2026-09-06-shared-read-guards.md)，shell 仍依赖批准，不是文件沙箱。

准备失败记录 not_executed；批准拒绝或取消不进入执行。提交前发现通常的外部变化返回明确拒写结果，模型必须重新读取、生成 diff 和申请批准，不能退回覆盖。动作检查点及结果不确定语义沿用[会话状态](../architecture/2026-09-21-atomic-session-storage.md)。

## Alternatives considered

- 完整内容覆盖并展示完整 diff：生成任意重写简单，但可能把未读内容和外部修改一并覆盖，且保留了绕过精确匹配的入口。
- 通用 unified patch 或模糊匹配：适合多处修改且能容忍上下文偏移，但会扩大解析、歧义和部分应用协议；目前单次唯一替换更容易验证，多处改动顺序读取和提交。
- 新建直接 wx 写目标：能排他拒绝覆盖，但写入失败可能留下不完整目标；临时文件加排他 link 先生成完整内容，接受文件系统支持限制。
- 保存批准到基于参数的通用缓存：重复操作方便，但外部环境变化会改变效果；文件变更逐次审阅，接受额外交互。

## Consequences

用户批准的候选与执行内容一致，常见外部编辑会被指纹检查发现；代价是额外读取、哈希、IO 和逐次批准。多文件不构成事务，原子替换不承诺断电持久性，检查到 rename 之间仍存在竞态，不能抵御恶意并发文件系统替换。需要敌对进程隔离时应使用操作系统级沙箱，而不是继续叠加字符串检查。

原子替换保留普通模式位，但不承诺保留扩展属性、ACL 或文件身份。新建失败可能遗留空父目录。内容变化后又完全恢复无法由纯内容指纹识别为历史事件；这不是协作编辑版本管理器。
