# 开发协作说明

项目通过 [AGENTS.md](../AGENTS.md) 组合两个独立的 Skill，并把具体学习信息保存在项目文件中。

| 部分 | 职责 | 迁移方式 |
| --- | --- | --- |
| [write-notes-like-deepseek](skills/write-notes-like-deepseek/SKILL.md) | 工程决策的格式、检索、维护和校验 | 按原样复用完整目录 |
| [learning-coach](skills/learning-coach/SKILL.md) | 讲解、练习、review 与学习交接的方法 | 可独立复制到其他学习项目 |
| [学习配置](learning/project.md)与[进度](learning/progress.md) | 本项目的背景、编辑分工、当前状态与证据 | 为新项目重新填写 |
| `notes/` | 本项目的工程决定和取舍 | 随本项目的代码维护 |
| [看板展示配置](board.json) | 项目流程、节点解释、依据链接与资料来源 | 按新项目填写；地图和学习区域都可省略 |

两个 Skill 互不依赖对方的内部文件，也不向对方增加分类或状态。`AGENTS.md` 声明当前项目选用的工作流及项目约定。

## 日常使用

新会话从根目录规则进入，按任务阅读项目配置、进度和相关决策。重大取舍先检索已有笔记，记录问题、选择、备选和代价；落地时同步实际代码与笔记的状态。

普通语法讲解无需写决策笔记。阶段收尾时更新当前学习进度，明确哪些是代码完成、哪些有理解证据、哪些验证尚缺失。源码默认由学习者维护，项目管理文件按授权直接维护。

从项目根目录运行：

```sh
npm run verify-notes
npm run board         # 生成可连接本地项目的 board.html
npm run board:bundle  # 生成含地图、进度和笔记的 board.snapshot.html
npm run test:board    # 检查地图、资料来源、解析与稳定同步
```

笔记校验使用现有 tsx 运行上游检查；看板生成和回归使用 Node.js，无新增依赖。笔记校验不验证设计语义、学习掌握程度或完整程序行为。笔记目录为空时上游检查也会成功，因此初次接入还需要确认实际文件存在。

- 更新时替换上游快照、核对变更并更新此提交号，再运行笔记校验。教学规则无需合并回上游。
- 上游约 4.7 MB，包含演示图片及看板模板；完整保留便于独立搬迁与核对来源。项目看板通过上述命令生成。
- 使用上游 `implemented` 模板时，不将标题前的维护提醒注释复制到正式笔记；校验器要求第一行就是 `# Agent Note:`。

## 项目对接约定

上游的非平凡变更规则用于工程取舍。教练 Skill 管理教学方式，进度文件管理学习证据，二者不改变 `proposed/implemented/rejected/archived` 或六种笔记类别。

项目补录既有决定时先保留可检索的源码路径与笔记到源码的链接，遵守学习者编辑源码的分工。有关源码反向注释的项目约定见 [AGENTS.md](../AGENTS.md)，不修改上游 Skill 来实现此差异。

新决定以首次提出日命名。历史补录使用最早可核实记录的日期，并在正文注明整理日期和 Git 依据；这不宣称已找到第一次私下讨论的时间。没有早期证据时使用整理日期。备选部分表达当前约束下的真实取舍，不把合理推断冒充当时做过的评审或实测。

现行笔记随代码更新：例如 2026-09-06 建立的 todo 持久化记录可以引用后续的缓存决定，而不重复新建一份相同的存储说明。过时的实现只在证据及取舍中说明，不列为当前有效能力。

## 看板内容与刷新

用 Chrome 或 Edge 打开 `board.html`，点击顶部“连接目录”，选择项目根目录或 `.agents`。这样可以一起读取 `board.json`、`notes/` 和配置明确引用的进度文件。目录及阅读偏好按页面路径和项目名保存，浏览器保留授权时自动恢复。

旧版保存的 `.agents/notes` 句柄仍可浏览笔记，但无法读取同级配置和学习资料；请重新连接项目根目录或 `.agents`。只连接 `notes/` 时页面明确提示这一范围，使用标准笔记分类，不沿用之前项目的地图与学习状态。

页面可见时每三秒检查一次，切回页面也会检查。所有页面共用顶部的连接、同步状态和手动检查按钮；手动检查在连接后出现。没有内容变化时保留 DOM；发生修改时保持节点展开、依据选择、当前笔记或进度原文、搜索、筛选、备选和学习区域偏好，以及焦点与阅读位置。读取失败或配置尚未保存完整时保留最后成功内容；删除配置会回退到笔记浏览，缺失的资料或章节会显示提示。

连接完整项目后，配置、笔记和进度正文的更新无需重新生成页面。修改模板、样式、浏览器逻辑或生成器后，需要重新运行生成命令并刷新网页。未连接的 `board.html` 显示生成时的地图和进度概览，笔记详情需要连接目录；页面会标示这个状态。

`board.snapshot.html` 同时内嵌生成时的地图、引用资料与完整笔记，适合直接阅读和脱机分享；更新快照运行 `npm run board:bundle`。默认不自动连接目录，也可以主动连接后切换为自动同步。

所有页面使用同一套顶部导航，没有常驻左右侧栏。首页以全宽地图展示主循环、返回路径、辅助状态与控制分支。点击节点，在所属行下方展开实际做法、限制、源码和决策依据；窄屏主流程与分支详情紧接所选节点。再次点击、关闭或 Esc 收起。每次只展开一个节点，依据可切换，备选方案可展开。顶部显示当前实现与下一步候选，下方列出验证缺口；学习记录默认折叠。节点关系来自明确的项目配置，不把笔记引用误画成运行时依赖。

顶部导航和模块筛选负责提示当前位置，正文直接展示内容。页面不再重复项目或模块标题、介绍段落、操作导语和页脚统计；阅读层只显示一次笔记原题。页面级标题保留给辅助技术和键盘导航。

决策资料使用卡片集合，演进记录和方案取舍保留各自的阅读方式，三者共用全文检索、模块和类别筛选。`/` 或 `Ctrl/Cmd+K` 聚焦搜索。演进记录按笔记日期绘制，同日期或同引用数按路径固定顺序。

完整笔记和进度原文在居中阅读层打开，保留全部章节、验证依据及正文下方的双向引用。关闭按钮、Esc、点击背景或浏览器后退回到原来的视图、筛选、展开节点和滚动位置；阅读中刷新也保留位置。关联资料继续在同一阅读层打开，“返回上一份资料”恢复前一份正文及其阅读位置。阅读层打开时，键盘焦点留在其中。

## 展示配置与可选学习区域

[board.json](board.json) 位于笔记目录同级，所有字段都属于展示层，不扩展 Skill 的分类和状态。

| 字段 | 内容与约束 |
| --- | --- |
| `name` | 导航中的项目名称 |
| `map.title` | 图内的短标题，例如“运行流程” |
| `map.nodes` | 每个节点的 `id/title/caption/behavior/boundary`、决策路径 `notes` 和可选源码链接 `sources` |
| `map.flow` | 二至六个主流程节点 ID，数组顺序就是展示顺序 |
| `map.loop` | 可选的 `from/to/label`，从后续步骤返回前面的步骤 |
| `map.supports` | 辅助节点的 `id/target/label`，指明它服务于哪一步 |
| `map.branches` | 控制分支的起点 `from`、标题 `title`，以及包含 `id/returnsTo/label` 的 `items` |
| `brief` | 当前概览的 Markdown `source`，以及 `current/next/attention` 对应的二级章节名 |
| `learning` | 可选的 `enabled/title/source/sections`；每个 section 指定展示 `title` 和原文 `heading` |
| `groups` | 决策资料的模块分组与入口顺序；每个笔记入口含规范路径 `id` 和可选短标题 `label` |

每个地图节点需要唯一 ID，并且在主流程、辅助模块或分支中出现一次；引用节点必须存在。源码路径相对于 `board.json` 所在目录，例如 `../src/agent.ts`。节点说明是便于浏览的解释，需要随实现维护；工程理由与验证证据仍链接到原始笔记。

`brief.source` 和 `learning.source` 是配置目录内部的 Markdown 相对路径，例如 `learning/progress.md`；渲染器不固定学习阶段或章节名称。当前概览取指定章节的首段，下一步说明取后续段落，待验证项取该章节的列表；完整原文始终可打开。阶段、运行证据与理解证据只在来源文件中维护，不在配置中再保存一份。

普通项目可以删除 `learning` 或设置 `"enabled": false`，继续使用地图与开发概览；也可省略 `brief`。两者不依赖教练 Skill。没有 `map` 时使用模块笔记清单，没有整个配置时按标准类别展示。`groups` 中缺失的旧路径会跳过，新增或改名后未配置的笔记自动进入对应类别；不会因地图未更新而从资料库中消失。笔记 ID 相对 `notes/`，中文译本仍使用不含 `.zh` 的规范路径。分组 ID 使用唯一的小写字母、数字和连字符，保留 `class-` 前缀给自动分类。

[项目生成入口](../scripts/build-notes-board.mjs) 与 [看板源文件](../scripts/notes-board/) 独立维护，原版 Skill 文件保持原样。两种页面共用解析器，原先的生成后正则补丁已由它接替。完整章节依据见[解析笔记](notes/implemented/process/2026-09-11-complete-board-sections.md)，布局与稳定同步依据见[工作台笔记](notes/implemented/process/2026-09-12-readable-board-and-stable-sync.md)。修改项目看板时使用项目 npm 命令，上游自己的生成命令仍输出原版页面。

浏览器脚本只读取笔记、配置和明确引用的项目资料，不在页面内改写源文件。跨笔记和进度来源链接在页面内打开，源码与外部证据链接另开页面；源码相对链接以生成文件所在项目为基准，搬到另一个项目时应在那里重新生成页面。目录连接依赖浏览器能力，其他浏览器仍可阅读离线快照。

## 迁移到另一个项目

1. 按需复制完整的 `skills/write-notes-like-deepseek/` 和独立的 `skills/learning-coach/` 到新项目的 `.agents/skills/`。只需要教学方法时可单独复制教练 Skill。
2. 在新项目根目录 `AGENTS.md` 中声明选用的 Skill，以及学习配置和进度文件的位置。教练 Skill 不要求这些文件沿用 mini-agent 的路径。
3. 根据新项目填写背景、源码编辑分工、验证入口和真实进度，创建用得上的笔记目录。新项目不继承本项目的笔记与完成状态。
4. 若使用相同目录布局和 tsx，可复用 `package.json` 的 `verify-notes` 脚本及相应 `.gitattributes` 规则。需要新版看板时复制 `scripts/build-notes-board.mjs` 与完整 `scripts/notes-board/`，以及两个 board 命令和 `test:board`。生成器支持 `--live/--bundle [输出文件] [项目名] [笔记目录]`，迁移时填写新项目名称。
5. 在新的 `.agents/board.json` 中填写该项目的流程、简短解释和依据路径。进度和学习来源按新项目的实际文件与章节配置；不需要学习区域时将其关闭。不继承 Mini Agent 的阶段、流程或理解证据，也可以完全省略配置，直接使用笔记浏览。源码入口、决策路径和资料章节的实际存在性由看板测试核对；内容含义仍需按源码审查。

仓库中的相对链接和项目级 Skill 目录可随 Git 一起迁移，无需个人电脑上的绝对路径。Codex 的项目 Skill 发现方式见 [官方文档](https://learn.chatgpt.com/docs/build-skills)，规则入口见 [AGENTS.md 官方文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。其他助手按其支持的入口加载同一份 Markdown 规则。
